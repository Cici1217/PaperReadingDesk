# 论文学习笔记生成指南

## 1. 笔记的目标

生成一份便于理解、复习和继续研究的中文知识笔记，而不是论文摘要、审稿意见或固定字段的内容填充。

笔记应重建论文的知识结构：先让读者知道论文在讨论什么、核心对象之间是什么关系，再逐层解释概念、分类、代表性工作、关键差异、问题和结论。读完笔记后，读者应能复述论文的整体框架，并解释重要概念之间的因果或对比关系。

## 2. 总体组织原则

1. **先给全局框架，再进入细节。** 开头用简短的“论文概述”说明主题、范围、核心对象和全文主线。如果论文围绕多个核心对象展开，先逐项给出一句话定义，并说明它们之间的关系。
2. **遵循论文自身的知识骨架。** 不要机械套用“贡献—方法—实验—局限”模板。综述论文按其分类体系组织；方法论文按问题、关键概念、系统组成或方法流程组织；实证论文按研究问题、变量、实验设计和证据链组织。
3. **从定义走向分类和判断。** 一个重要主题通常按以下顺序展开：定义或作用 → 核心矛盾/评价维度 → 分类 → 代表性工作或证据 → 类别间差异 → 当前问题。
4. **强调关系，而不是堆积事实。** 明确写出为什么要这样分类、不同类别如何取舍、某个设计解决了什么问题、结论由什么证据支持。
5. **由浅入深。** 第一次出现重要公式、变量、动作空间、数据形式或评价指标时，用普通中文解释。不能只抄公式或术语。
6. **结尾逐层收束。** 先分别总结各主线的主要局限，再整理可能的解决路线或未来流程，最后用少量要点概括论文的核心观点。
7. **先判断论文类型，再决定讲解重心。** 不同类型的论文不能套用同一种笔记密度和目录；应以论文最主要的研究形态为准，必要时组合两种组织方式，但必须有一条清晰主线。

## 3. 按论文类型决定组织方式

### 3.1 综述、Survey 与系统性回顾

重点是帮助读者建立领域地图，而不是逐篇罗列被引用工作。

- 先说明综述覆盖的范围、排除的范围，以及作者使用什么轴线组织领域。
- 围绕 2～5 条主要脉络建立分类树，例如模型结构、训练范式、数据来源、任务形式或评价方式。分类必须来自论文，或能由论文内容直接支持。
- 每条脉络解释“为什么这样分类”“各类别解决什么问题”“类别之间如何演进或取舍”，再选择少量真正有代表性的工作作为锚点。
- 比较代表性工作时使用统一维度，优先使用紧凑表格或归纳段落，避免为每篇工作重复一套机械字段。
- 最后归纳跨类别共同存在的瓶颈、尚未统一的评价标准和可能的研究方向，使笔记形成有层次的领域认识。

### 3.2 模型、算法与方法论文

重点是让读者能够从问题定义一路复述到模型输出，并理解每个关键设计为什么存在。

- 先定义任务、输入、输出、监督信号、优化目标和作者要解决的具体瓶颈。
- 以端到端 pipeline 为主线，按数据进入模型后的真实顺序解释：数据或观测 → 表征/编码 → 核心模块或算法步骤 → 训练目标 → 推理或控制输出。
- 对每个关键模块回答：它接收什么、输出什么、内部做什么、解决了前一步的什么问题、与基线或常见做法有什么差别。
- 选择决定方法本质的关键公式，而不是搬运所有公式。对每个公式解释符号、计算过程、直观意义、它在训练或推理中的位置，以及改变该项会产生什么影响。
- 明确区分训练阶段与推理阶段；涉及控制或序列决策时，还应说明观测、动作空间、时间窗口、控制频率或 rollout 方式（仅限论文提供时）。
- 实验部分围绕“哪些证据验证了哪些设计”组织，重点解释主结果、消融实验、泛化测试和失败案例，不按表格顺序逐项抄数。

### 3.3 实证、Benchmark、数据集与系统论文

- 实证论文按研究问题、变量/干预、实验设计、证据链与可归因范围组织。
- Benchmark 或数据集论文重点解释覆盖范围、数据采集与标注、任务和指标设计、数据偏差，以及指标是否真正测到目标能力。
- 系统论文重点解释组件边界、信息流、部署条件、延迟或资源约束，以及各组件对整体结果的作用。
- 如果论文兼具多种类型，选择最能解释其核心贡献的一类作为主结构，其他类型只作为补充视角，不要并排生成多套重复目录。

## 4. 推荐的章节形态

章节标题必须根据论文内容命名。下面是组织逻辑，不是要求逐字照搬的固定目录。

```markdown
# 论文标题

## 1. 论文概述
- 论文讨论的范围
- 2～5 个核心对象及其一句话定义
- 对象之间的关系或论文的总体框架

## 2. 必要的基础概念
- 核心定义、公式或任务设定
- 公式中各变量的含义
- 重要概念内部的进一步分类

## 3. 第一个核心主题
### 3.1 分类或分析维度 A
### 3.2 分类或分析维度 B

## 4. 第二个核心主题
...

## N. 主要局限与尚未解决的问题

## N+1. 未来方向或可能的技术路线

## N+2. 总结
- 全文最重要的 3～6 个判断
```

如果某一部分不适用于论文，应删除或改名，不要为了完整而制造空洞章节。章节数量由论文内容决定。

## 5. 每个主题如何展开

### 5.1 定义与作用

第一次出现一个核心对象时，先用一两句话回答：

- 它是什么？
- 它在整个问题中起什么作用？
- 它与相邻概念有什么区别？

### 5.2 核心矛盾或评价维度

尽量找出作者组织材料的真正轴线，例如真实性与可扩展性、性能与成本、任务复杂度与环境复杂度。只有论文确实支持时才提炼，不得为了形式强造“矛盾”。

### 5.3 分类和对比

- 使用层级标题和项目符号呈现清晰的分类树。
- 每一类先说明共同特点、优点、缺点或适用场景。
- 对比必须使用一致维度，避免把不相干的特点并列。
- 分类结束后，用一小段话解释这些类别之间最重要的差异。

### 5.4 代表性工作、数据集或实验

采用“**名称**：一句话定位”的写法。每项优先保留：

1. 它是什么；
2. 使用了什么关键数据、机制或实验设置；
3. 主要解决或检验什么问题；
4. 与同类工作的辨识度。

不要把论文名称排成没有解释的清单，也不要为每项编造统一字段。

### 5.5 解释与判断

在事实之后补充必要的综合判断，例如：

- 这一结果说明了什么；
- 为什么某项指标不足以诊断失败；
- 哪些因素被同时改变，因此无法归因；
- 哪个结论是论文直接证据，哪个只是合理推论。

## 6. 公式、图表和术语

- 保留真正帮助理解的关键公式，并在公式下逐项解释符号、输入、输出及直观含义。行内公式必须放在 `$...$` 中，独立公式必须放在 `$$...$$` 或 `\[...\]` 中，不能输出没有数学分隔符的裸 LaTeX。
- 如果输入提供 `paperImages`，主动筛选真正帮助理解核心内容的图片，优先级依次是：总体方法架构、端到端流程或 pipeline、核心算法步骤、关键模块关系、任务或数据流程，以及能直接支撑核心结论的主结果图。
- 通常选择 1～4 张重要图片即可；图片较多时宁缺毋滥，不要把图片库全部插入笔记。装饰图、重复结果图、信息不足的裁剪图、仅列大量数字的次要表格通常不选。
- 图片必须放在解释它的相应章节附近，使用 `![具体图注](markdownSource)`，并在图片前后说明“图中信息如何流动、它帮助理解什么、应关注哪一部分”。不能只插图不解释。
- 只能使用输入 `paperImages` 给出的 `markdownSource`，不能修改路径、猜测图片内容或虚构论文中不存在的图片。无法确认图片与正文含义时不插入。
- 中文解释为主，所有关键技术术语第一次出现时必须同时给出规范中文与英文全称/常用缩写，统一采用“中文（English Full Term, ACRONYM）”或“中文（English Term）”格式。例如：`大语言模型（Large Language Model, LLM）`、`均方误差（Mean Squared Error, MSE）`。如果论文只使用缩写且无法从正文可靠确认英文全称，则写作“中文（ACRONYM）”，不得猜测扩写。后续可直接使用中文、英文简称或缩写，避免每次重复全称。
- 术语的中英文必须指向同一技术概念，不能只在“关键概念”列表中补英文；正文、标题、图注或表格中第一次引入该术语时就应完成中英对照。
- 保留模型名、数据集名、Benchmark 名、缩写和必要的英文检索词。
- 保留有意义的数值、实验条件和比较结果；不能把定量证据改写成模糊的“效果很好”。

## 7. 如何使用用户摘录和问答

- 用户摘录表示用户关注的内容，应提高相关主题的解释深度，并放回它所属的知识位置。
- 不要单独建立“我的摘录”章节，把摘录原样堆在一起。
- 已回答的问题应转化为相关段落中的解释、证据或未决问题。
- 用户材料与论文正文冲突时，以可核实的论文内容为准，并明确指出不确定性。

## 8. 内容密度与写作风格

- 使用准确、直接、可复习的简体中文。
- 以短段落为主，只在分类、步骤、条件或结论确实适合并列时使用项目符号。不要把每句话都拆成条目。
- 控制条目数量：一个小节通常使用 0～5 个项目符号；确有复杂分类时可以更多，但应先分组或改用表格，避免连续出现十几个同级条目。
- 每个二级章节应有一段承担解释和串联作用的正文，不能由标题加项目列表堆成提纲。相邻条目表达同一逻辑时，应合并为一个完整段落。
- 每个项目符号应表达一个完整判断，而不是只放一个名词。
- 先解释再使用术语，避免连续堆叠英文名词。
- 不使用“本文非常重要”“取得显著成果”等空泛评价。
- 不冒充用户写个人感想，不虚构“与我的研究的联系”。只有用户摘录或问答明确提供了这种联系时才写。
- 不重复同一结论；详细内容放正文，结尾只做压缩和收束。

## 9. 事实约束

- 只能使用提供的论文正文、已有概括、用户摘录和已回答问题。
- 不得补写输入中不存在的实验、数字、贡献、因果关系或作者观点。
- 明确区分论文主张、实验观察和笔记撰写者的综合归纳。
- 信息不完整时，直接说明“论文提供的内容不足以判断”，不要猜测。

## 10. 最终输出要求

- 输出一篇完整 Markdown 笔记，从一级标题 `# 论文标题` 开始。
- 严格使用可编译的 Markdown：强调内容使用 `**文字**`，公式使用上述数学分隔符，不要用代码块包裹普通公式。
- 使用连续、正确的数字章节编号。
- 标题应描述实际内容，避免使用“方法”“结果”之类过于宽泛的标题，除非它确实最准确。
- 笔记必须自洽：读者不打开原论文，也能理解主要框架、概念和结论。
- 内容详略由论文的信息密度决定，不设固定字数，也不要为了变长而重复。
- 输出前检查：主线是否适合论文类型、条目是否过多、方法论文的 pipeline 与关键公式是否讲清、综述论文是否形成有层次的分类关系、插入的每张图片是否重要且得到正文解释、每个关键技术术语首次出现时是否已经给出中英对照及可靠缩写。
